Ans: Constraint Violations for Update Operation 
When we update data in a database, the new value must follow the defined constraints. If it 
breaks any rule, it is called a constraint violation. 
Constraints include: 
• Primary key constraint – No duplicate and no null values allowed. 
• Foreign key constraint – Value must match an existing value in another table. 
• Unique constraint – No duplicate values allowed. 
• Not Null constraint – Value cannot be empty. 
• Check constraint – Data must satisfy a condition.

Q6. Evaluate various strategies for handling constraint violations in relational database 
systems. 
When a database operation violates a constraint, the system must handle it to maintain data 
integrity. Common strategies include: 
1. Reject the Operation 
• The database refuses the insert, update, or delete that violates the 
constraint. 
• Example: Trying to insert a duplicate StudentID is rejected. 
•    Ensures strict data integrity. 
2. Set Default or Null Values 
• Replace missing or invalid values with a default value or NULL if allowed. 
• Example: Age missing → set default age = 18. 
• ⚠ May not always reflect real data. 
3. Cascade Updates or Deletes 
• Automatically update or delete related records to maintain referential 
integrity. 
• Example: Deleting a Course automatically deletes all Enrollment records 
for that course. 
4. Raise an Error with Custom Message 
• Database generates an error message to inform the user about the 
violation. 
• Example: “Cannot insert duplicate primary key.”

8. Evaluate different approaches to implementing class hierarchies in database systems. 
Class hierarchies represent inheritance relationships in databases. There are three common 
approaches: 
1. Single Table Inheritance (Table per Hierarchy) 
• Description: All classes in the hierarchy are stored in one table. 
• Implementation: Add a Type column to identify subclass. 
• Advantages: Simple, easy to query. 
• Disadvantages: Many NULLs for fields not used by all subclasses. 
• Example: Shape table with columns: ShapeID, Type, Radius, Length, Width, Base, 
Height. 
2. Class Table Inheritance (Table per Class) 
• Description: Each class has its own table with all attributes. 
• Advantages: No NULLs, clear separation of subclasses. 
• Disadvantages: Querying requires joins between parent and child tables. 
• Example: Shape table (ShapeID, Color, Type), Circle table (ShapeID, Radius), 
Rectangle table (ShapeID, Length, Width). 
3. Concrete Table Inheritance (Table per Concrete Class) 
• Description: Only concrete subclasses have tables; parent class table may not 
exist. 
• Advantages: No joins needed, all attributes in one table per subclass. 
• Disadvantages: Redundant storage of parent attributes in each subclass table. 
• Example: Circle table (ShapeID, Color, Radius), Rectangle table (ShapeID, Color, 
Length, Width). 
Summary: 
• Single Table: Simple, but many NULLs. 
• Class Table: Clear structure, needs joins. 
• Concrete Table: No joins, but redundancy exists.

Parallel Query Optimization: 
• It is the process of dividing a query into smaller parts and executing them 
simultaneously using multiple processors. 
• It improves query execution speed and system performance. 
• The optimizer selects the best execution plan for parallel processing. 
Steps in Parallel Query Optimization: 
1. Query Decomposition – Break the query into smaller sub-queries. 
2. Data Partitioning – Divide data into parts for parallel execution. 
3. Task Allocation – Assign sub-tasks to different processors. 
4. Result Merging – Combine results from parallel tasks. 
Optimization Strategies: 
1. Horizontal Partitioning 
o Data is divided into rows across multiple processors. 
o Improves performance for large tables. 
2. Vertical Partitioning 
o Data is divided by columns. 
o Useful when queries access limited attributes. 
3. Cost-Based Optimization 
o Selects the execution plan with the lowest estimated cost. 
o Improves efficiency by reducing resource usage. 
4. Rule-Based Optimization 
o Uses predefined rules to choose execution plans. 
o Simpler but less flexible than cost-based. 
Effect on Performance: 
• Reduces query response time. 
• Improves resource utilization. 
• Handles large datasets efficiently. 
• But excessive parallelism may increase communication overhead. 
Q2. Evaluate the effectiveness of different recovery techniques in distributed 
transactions for ensuring fault tolerance and atomicity 
Distributed Transactions: 
• A transaction that runs on multiple distributed databases or nodes. 
• Must maintain atomicity, consistency, and fault tolerance even if failures occur. 
Recovery Techniques: 
1. Two-Phase Commit (2PC) 
• Used to ensure atomic commitment across all participating nodes. 
• Phase 1: Coordinator asks all nodes to prepare. 
• Phase 2: If all nodes agree → commit; otherwise → abort. 
•    Ensures strong atomicity. 
•   Slow and may block if coordinator fails. 
2. Three-Phase Commit (3PC) 
• Improved version of 2PC. 
• Adds an extra phase to reduce blocking. 
• Nodes move through prepare → pre-commit → commit. 
•    Reduces blocking problem. 
•   More complex and high communication cost. 
3. Logging and Checkpointing 
• Transactions record changes in a log file. 
• If failure occurs, system restores data from logs or checkpoints. 
•    Helps in fast recovery. 
•   Log management increases storage overhead. 
4. Replication-Based Recovery 
• Data is copied to multiple nodes. 
• If one node fails, data is recovered from another replica. 
•    High availability and fault tolerance. 
•   Requires extra storage and synchronization.

Q4. What are the two phases in the Two-Phase Commit (2PC) protocol? 
The Two-Phase Commit (2PC) protocol ensures atomicity in distributed transactions. It has 
two phases: 
1. Prepare Phase (Voting Phase) 
• The coordinator asks all participating sites to prepare for commit. 
• Each site checks whether it can commit the transaction. 
• Sites send their vote (Yes/No) to the coordinator. 
2. Commit Phase (Decision Phase) 
• If all sites vote Yes, the coordinator sends a Commit message. 
• If any site votes No, the coordinator sends an Abort message. 
• All sites follow the final decision. 
Q5. What are the three phases in the Three-Phase Commit protocol? 
The Three-Phase Commit (3PC) protocol improves 2PC by reducing the blocking problem. It 
has three phases: 
1. Can-Commit Phase 
• The coordinator asks all participating sites if they can commit. 
• Sites check and send their vote (Yes/No) to the coordinator. 
2. Pre-Commit Phase 
• If all sites vote Yes, the coordinator sends a Pre-Commit message. 
• Sites prepare to commit and acknowledge the message. 
3. Commit Phase 
• After receiving acknowledgments, the coordinator sends the Commit message. 
• If any site votes No, the transaction is aborted. 
Q6. Explain shared-memory and shared-disk architectures. 
1. Shared-Memory Architecture: 
• Multiple processors share the same memory and disk. 
• Processors communicate through common shared memory. 
• Suitable for small systems with limited processors. 
Advantages: 
• Fast communication between processors. 
• Easy to manage and implement. 
Disadvantages: 
• Not scalable for large systems. 
• Memory contention may reduce performance. 
2. Shared-Disk Architecture: 
• Processors have separate memory but share the same disk storage. 
• Each processor accesses the common disk independently. 
Advantages: 
• Better scalability than shared-memory. 
• Processors work independently. 
Disadvantages: 
• Disk access conflicts may occur. 
• Requires synchronization to avoid data inconsistency.

Q8. List the types of parallelism used in query processing. 
The main types of parallelism used to improve query performance are: 
1. Inter-Query Parallelism 
a. Multiple queries are executed simultaneously. 
b. Improves system throughput. 
2. Intra-Query Parallelism 
a. A single query is divided into sub-queries and executed in parallel. 
3. Inter-Operator Parallelism 
a. Different operators (SELECT, JOIN, PROJECT) in a query run at the same time. 
4. Intra-Operator Parallelism 
a. A single operator is divided into parts and processed in parallel on data 
partitions. 
Q9. Define distributed catalog management. ? Explain the role of a catalog in distributed 
databases. 
Definition: 
• Distributed catalog management is the process of storing and managing metadata 
about database objects in a distributed database system. 
• The catalog information is stored at multiple sites and contains details about tables, 
fragments, locations, users, and constraints. 
Role of Catalog in Distributed Databases: 
• Stores information about data location and fragmentation. 
• Maintains details about tables, attributes, indexes, and users. 
• Helps the system locate data quickly during query execution. 
• Supports query optimization by providing metadata. 
• Ensures proper data management and coordination between different sites.

A Distributed DBMS (DDBMS) stores data at multiple sites but manages it as a single

• Each site has its own database and processor.
